# Version 5 review, first increment (ECHO 2026-10-06)

Review of commit `6897f4964` ("Version 5, first increment: ledger links, 3-phase loop, negotiations, mixed live modes"). All 1075 tests pass, but the new mid-turn resume and negotiation paths are only exercised on a scenario without a store, without emergent tracking and without negotiations – which is why most of the findings below go undetected. Findings marked "reproduced" were confirmed by running code; the rest come from reading the code.

Suggested priority: 1, 2, 3 and 7 – they affect run correctness and the headline feature, and each is a small fix.

## Code flaws

### 1. Mid-turn resume dead-ends after a partial actors phase (reproduced)

`detect_last_phase` (`scenario_lab/resume.py:76`) marks the actors phase complete as soon as *any* actor `.md` file exists. Actor files are saved one by one as each parallel call finishes. A crash with 1 of 4 actors answered makes `resume` skip to the world phase, and `_load_actors_phase` then raises "government.md is missing". The run cannot be resumed without manual cleanup.

The `phases` record in `summary.json`, written only after statement and store changes are applied, is the reliable signal, but detection never reads it.

### 2. Mid-turn resume restores the wrong store snapshot

`_load_actors_phase` (`scenario_lab/orchestrator.py:740`) affects europe-2032:

- If `4-world-store.json` exists, it restores the *post-world* state. That happens when a crash hits the referee or summary call – a common place for API failures. The world step then reruns on top of it: adjustments are applied twice and added records are duplicated.
- Otherwise it restores the *first* actor's `-store.json`, which is saved right after actor 1's writes only. Actors 2…N lose their store writes for the turn.

The same first-actor choice appears in `_history_snapshot` in `store.py` (whose docstring wrongly says the actor files "agree on contents") and in the existing full-turn restore in `resume.py`. The latter is latent today, since it only bites scenarios with a store but no world tables, and none exist yet.

### 3. Mid-turn resume drops emerging-development tracking

`_load_events_phase` never calls `_update_emerging_developments`. For europe-2032 and forking-futures (`track_unfired: true`) the resumed turn renders and persists a stale list. The byte-identical reproduction test uses sweden-ai-2030, which has no tracking enabled. The evaluations are persisted in `1-event-evaluations.json`, so the reload can replay them.

### 4. `info_file` validation breaks for yaml paths and variants (reproduced)

`validate scenarios/x` passes, but `validate scenarios/x/scenario.yaml` and `validate …/variants/acceleration.yaml` both fail with "info_file not found". `validator.py:1538` resolves against the given path instead of the scenario directory.

### 5. Negotiation artifacts mix attempts

When the actors phase reruns, `messages.json` merges messages from the aborted attempt (`_negotiation_history` reads the old file back), and stale `round-NN.md` files from a longer earlier attempt remain.

### 6. Smaller issues

- Progress display: all world sub-steps call `start_step(3)` (`orchestrator.py:538–588`), so the tracker shows "Updating metric rules" for metrics, referee and summary.
- `--max-runs` ("most recent N"): `iter_run_dirs` sorts by path, so subfolder runs sort before top-level runs regardless of date.
- `branch` places the child in `runs/` even when the parent lives in a subfolder.
- `live <run> --turn N` regenerates menus without `llm_actors` (`cli.py:3521`), so a mixed game silently becomes all-human. Separately, a mode changed at `live-resolve --llm-actors` does not carry into the chained next menus, which read the old `menu.json` record.
- `config.json` does not record the negotiations settings, so batches with and without negotiations (for example via `--override negotiations.enabled=true`) are indistinguishable in cohort analysis.

## Functionality flaws

### 7. Negotiation-round prompts contradict themselves (confirmed by rendering)

The round instruction ("do not describe your actions, reply under `## Messages`") sits mid-template. Both the system and the user prompt then end with "Respond with a Markdown text containing … Heading level 2: Actions …", and `## Messages` is never part of the output format. Expect full action write-ups and unreliable message parsing. A custom actor template without `{{negotiation_instructions}}` would silently never ask for messages at all; the validator only checks for `negotiation_messages`.

### 8. Senders never see their own notes

Inboxes hold received messages only. If A proposes a deal and B answers "agreed", A writes its actions seeing only "agreed", without its own offer. Rejected notes are not reported back to the sender. The Game Master never sees any negotiation, so it cannot hold actors to agreements or price leaks – possibly intended, but worth an explicit decision.

### 9. `max_rounds` is inert

Rounds after `rounds` have no participants (`participants_for_round` only seats actors with `actor_rounds >= round`), so the loop breaks. Checked directly: with `rounds: 2` and any `max_rounds`, round 3 has no participants. ARCHITECTURE.md, the docstring and the validator's cost warning all describe extension "while rounds keep delivering". The "dynamic round count" from the VERSION 5 notes is not implemented.

### 10. Metaculus anchors never reach a prompt

Anchors are parsed, validated, patchable and shown in `describe`, but no template or prompt builder uses them. The proposal and both skills say "the figure is a prior the Game Master adjusts" – the Game Master never sees it. There is also no tool for the planned first test (Game Master turn-1 pricing versus market figure).

### 11. `info_file` and `read_table_history` have no consumers

`info_file` is validated but never rendered – not in turn prompts, not in `describe` (filename only), not in sign-off. `read_table_history` has no caller in the CLI or the analysis code. The proposal marks both "done"; in practice they are scaffolding.

### 12. Analysis pools everything

Output subfolders and the update skill's incomparability rule exist to keep batches apart, but `ensemble`, `synthesize` and `calibrate` now pool all subfolders with no way to restrict to one. An in-place scenario update leaves the scenario identity (name + actors) unchanged, so `mixed_scenario_warning` cannot catch the mix either.

### 13. Branching keeps later one-shot events (pre-existing, not v5)

`create_branch` copies the parent's full `occurred_events` (`resume.py:538`), and `load_run_state` does not truncate it at the branch turn the way it truncates `event_log`. A non-repeatable event that fired *after* the branch point in the parent can never fire in the branch, which biases what-if comparisons. `finalize_summary` then unions the parent's set into the branch's final summary.
