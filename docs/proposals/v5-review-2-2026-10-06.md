# Version 5 review, second pass (ECHO 2026-10-06)

Review of commit `3ae23f96d` ("Version 5: fix all thirteen review findings"), which addressed `v5-review-2026-10-06.md`. All 1087 tests pass, and the earlier reproduction of the partial-actors resume failure now passes. This file lists only what still needs fixing: one regression introduced by the fix commit, the remaining issues, and what is still open from the first review.

Suggested priority: A and B before anyone enables negotiations or relies on mid-turn resume of europe-2032.

## A. Negotiation rounds after the first are blind (high, regression)

Confirmed by rendering a round-2 prompt. Two causes:

- In `templates/user-prompts/actor.md`, the "Private messages to you" block now sits only in the `{% else %}` (action) branch, so round prompts never render `negotiation_messages`.
- `run_note` in `_run_negotiations` (`scenario_lab/orchestrator.py`) does not pass `negotiation_outbox`, so the sender's own notes are missing too.

In round 2 and later an actor sees neither what it received nor what it sent, while the round text says "for context on the replies above". Notes still reach the final action prompt and the Game Master record, but no actor can answer another's note, which is the point of multiple rounds. Fix: render the inbox in the round branch, pass the outbox from `run_note`, and add a test asserting that a round-2 prompt contains both.

## B. A crash during store changes is still unsafe to resume (medium)

`detect_last_phase` (`scenario_lab/resume.py`) counts the actors phase as complete once every actor has its response and `-statements.md` file. In `_apply_actor_phase_state`, all statement files are written before store changes are applied, and the store step can include LLM re-ask calls. A crash there makes resume skip the actors phase, and later actors' store writes are silently lost. Fix: when the scenario has a store, also require every actor's `-store.json`, or read the `phases` record in `summary.json`, which is written after both steps.

## C. `_history_snapshot` can still pick the wrong file (low to medium)

`_history_snapshot` (`scenario_lab/store.py`) now picks the per-actor snapshot with the highest summed record counters. Counters only increase on `add`, so in a turn with only updates or deletes, all snapshots tie and the alphabetically last file wins (`>=` over sorted names), not the last one written. Fix: walk the actor order from the run's `config.json`, as `detect_last_phase` does, and take the last file present.

## D. Live mixed mode is only partly kept (low)

`run_live_menu_command` (`scenario_lab/cli.py`) falls back to `recorded_llm_actors(run_dir, args.turn)`, the mode recorded for the same turn. Generating the next turn's menus by hand (for example after `live-resolve --no-auto-menu`) finds no record and reverts to all-human. Fix: fall back to the latest earlier turn's record. Also, there is no way to switch a mixed game back to all-human, since an empty flag falls back to the recorded mode; an explicit opt-out (for example `--llm-actors none`) would cover it.

## E. Smaller points

- `--max-runs` ordering: `iter_run_dirs(order="recent")` sorts by directory modification time, which changes when a run is resumed or when Dropbox touches it. Sorting on the timestamp in the run name is more reliable.
- `negotiations.rounds` is now redundant: participants and the round cap both use `max_rounds`, so `rounds` only feeds the validator's cost warning. Either drop it (letting `max_rounds` default as today) or make it a guaranteed minimum before the silent-round stop applies.
- `market-check` (`scenario_lab/market_check.py`) compares forced events (evaluations with `pinned: true`, probability 1.0) against market figures. Skip pinned entries or label them.
- `validate_negotiations` checks custom system prompts for a `negotiation_round` branch, but custom user prompts only for the variable names. A custom `user-prompts/actor.md` that renders both variables without branching on `negotiation_round` still sends the action format in rounds. Warn on `negotiation_round` there too.
- Legacy runs whose `event_log` started partway through: `load_run_state` and `create_branch` now restrict `occurred_events` to ids in the stamped log, so one-shot events that fired before the log existed can fire again. This is an edge case, but a run is only "legacy" when it has no log at all, so the guard does not cover it.
